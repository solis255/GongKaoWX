# 国考客观题 JSON 题库原型设计

## 目标

为考公刷题微信小程序制作可验证的本地 JSON 题库原型。首版只包含国家公务员考试客观题，不包含申论等主观题。题库用于验证刷题、答题解析、错题和统计流程，不作为最终生产数据库方案。

## 题库范围

按照 2026 年国考公共科目笔试大纲，将客观题拆分为六套题库，每套 60 题，共 360 题：

| 文件 | 模块 | 题量 |
| --- | --- | ---: |
| `politics.json` | 政治理论 | 60 |
| `common-sense.json` | 常识判断 | 60 |
| `verbal.json` | 言语理解与表达 | 60 |
| `quantitative.json` | 数量关系 | 60 |
| `reasoning.json` | 判断推理 | 60 |
| `data-analysis.json` | 资料分析 | 60 |

所有文件放在项目根目录的 `questions/` 文件夹。资料分析按共享材料分组，每份材料包含 5 道题。

## 内容来源策略

1. 检索国家公务员局及其他政府网站公开的大纲、政策、法律法规、统计公报和公开数据。
2. 检索往年真题页面和第三方题库，用于研究题型、知识点分布、难度和常见设问方式。
3. 默认重新命题，不批量照搬第三方题干、选项和解析。
4. 每道题记录可追溯的来源链接；无直接事实来源的原创逻辑、数学题标记为 `original`。
5. 政治理论和时效性常识必须记录资料发布日期与访问日期，便于后续更新或下线。

## 生成方式

并行调度六个独立 subagent，每个 subagent 只负责一个模块和一个 JSON 文件，避免共享写入冲突。所有 subagent 使用同一 JSON Schema、ID 规则、难度比例和来源规则。

目标难度比例为：简单 18 题、中等 30 题、困难 12 题。每题均为四选一，只有一个正确答案。

## JSON 结构

每个题库文件包含元数据、可选材料和题目数组：

```json
{
  "version": 1,
  "category": "数量关系",
  "title": "国考数量关系题库",
  "questionCount": 60,
  "materials": [],
  "questions": [
    {
      "id": "quantitative-001",
      "category": "数量关系",
      "subtype": "工程问题",
      "difficulty": "medium",
      "stem": "题干",
      "materialId": null,
      "options": [
        { "key": "A", "text": "选项 A" },
        { "key": "B", "text": "选项 B" },
        { "key": "C", "text": "选项 C" },
        { "key": "D", "text": "选项 D" }
      ],
      "answer": "B",
      "explanation": "完整解析",
      "knowledgePoints": ["工程问题"],
      "sourceRefs": [
        {
          "kind": "official",
          "title": "中央机关及其直属机构2026年度考试录用公务员公共科目笔试考试大纲",
          "url": "https://www.forestry.gov.cn/c/www/gsgg/645383.jhtml",
          "publishedAt": "2025-10-16",
          "accessedAt": "2026-06-18"
        }
      ],
      "status": "draft"
    }
  ]
}
```

共享材料使用 `materials` 数组保存，题目通过 `materialId` 引用，避免在资料分析题中重复存储大段材料。
`sourceRefs` 可以为空；仅原创且不依赖外部事实的逻辑题和数学题使用空数组。引用时效性事实时，`publishedAt` 和 `accessedAt` 都必须填写。

## ID 与文件规则

- ID 前缀分别为 `politics`、`common-sense`、`verbal`、`quantitative`、`reasoning`、`data-analysis`。
- 编号从 `001` 到 `060`，在整个项目内唯一。
- 文件编码为 UTF-8，JSON 使用两个空格缩进。
- `questionCount` 必须与 `questions` 实际长度一致。
- 题目不得依赖外部图片才能作答；需要图形时，首版使用可文本表达的图形关系。

## 校验与质量控制

生成完成后运行统一校验：

1. 所有 JSON 文件可解析，并符合 `questions/schema.json`。
2. 每个文件恰好包含 60 题，ID 唯一且连续。
3. 每题有 A、B、C、D 四个非空选项，答案必须命中其中一个选项。
4. 每题包含非空解析、知识点、难度和状态。
5. 检查题干和选项的完全重复及高相似重复。
6. 数量关系和资料分析由独立复核任务重新计算。
7. 政治理论、常识判断的时效性事实与来源日期一致。
8. 抽查解析是否泄露答案、是否存在多个合理答案或信息不足。

校验失败的题目保持 `draft`，修正并复核后才改为 `reviewed`。原型允许读取 `draft`，但界面应保留“内容待复核”标识。

## 原型读取方式

小程序按模块加载对应 JSON 文件，先读取文件元数据，再按顺序或随机抽取题目。答题时只保存题目 ID、用户答案、是否正确、耗时和答题时间；错题本通过题目 ID 回查原题。

首版不把全部题库合并为一个文件，避免单文件过大，也方便后续将单个模块迁移到数据库。

## 错误处理

- JSON 加载失败时显示模块暂不可用，不影响其他模块。
- 找不到 `materialId` 时跳过该题并记录错误。
- 题目字段缺失或答案非法时不进入刷题队列。
- 来源失效不阻塞答题，但在内容维护清单中标记待更新。

## 验收标准

- `questions/` 下存在六个题库文件和一个 `schema.json`。
- 每套题库 60 题，总计 360 题，全部为四选一客观题。
- 六套文件均通过结构、数量、ID、答案和重复性校验。
- 数量关系和资料分析通过独立计算复核。
- 随机抽查每套至少 10 题，题干、答案和解析相互一致。
- 文件能够被微信小程序直接解析和按模块读取。
